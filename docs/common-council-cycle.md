## 共通契約と再利用

- cities.json：公式入口・名簿/議案経路（確認できないものはnull）、provider、
  tenant、任期根拠、週次案（無効）、品質ポリシー。京都の承認済みガードSHAだけを固定。
- providers.py：ネットワークを持たないSSPのJSON/限定JSONPデコード。
  保存原本をreceiptのPOST URL/200/byte数/SHA、TLS/転送/再試行条件、
  approvalのreference/guard/run、receipt.meeting_scopeの会議/年/scopeへ照合。
  京都旧形式のtenant補完は京都日程の既存専用scopeだけに限定。
  新しい都市に京都の承認を流用しない。実原本のguard未受入なら拒否する。
- 年は公式会期索引、月日は公式日程名から組み立てる派生値であり、他都市の年度/
  暦年対応を認証したとは扱わない。材料/日付不明はHOLD。索引/日程のJSON位置を保持。
  minute_idは原本にある値だけを保持。話者区分はunverifiedで、既存IDを再採番しない。
- 比較キーはcity:council_id:schedule_id。公共の人物/発言IDを新規発行するものではない。
- cycle.py：都市非依存。初回はimmutable baseline-only、同版はsource review0。
  新着会議はunverified候補。本文の同件数訂正、話者/会議名/日付の変更、追補、
  発言や会議の欠落はHOLDしlast_goodの記録を保持。既知版の巻戻りも現在のlast_goodと比較し、
  same-version-HOLDと根拠を観測記録へ残す（重複source review0）。
- minutes_update_guard.pyのキー/本文fingerprint・訂正/削除/継続会議のfail-closed思想を
  再利用し、同ファイルや固定生成器を変更/実行しない。既存_private境界と_hash_fileを再利用。
- 私有の新しいnormal.jsonと週別attempt journalだけを使い、既存CAS・receiptを上書きしない。
  source SHA+設定スコープ、期待normal SHA、ロック、atomic replaceを検査。
  失敗時は旧normal保持。失敗した同一週も再実行拒否。孤立tempは保全しPMが復旧判断。
  複数scopeを同じbaselineとして比較しない。
- last_goodは正常な非公開観測であり、議事録/人物/議案の認証factや公開許可ではない。
  原典収録完全性は常にunknown。公式取得権限をこのサイクルから発行しない。

## 実運用GO条件

本Draftのコード受入と、各scopeの原典/任期/同一性/完全性限界・private保存先/設定/
コードSHA・審査担当・失敗復旧を別途受入。取得は既存の通信ガードと個別の承認を使う。
未知の都市の必要資料は設定の公式入口、会期/日程/本文1件、日時点名簿/任期、
議案/議決原典。正確なIDがない段階で本文URLを推測しない。
将来の初回計画はsession GET1+索引POST1（合計2、各2MiB/25秒等）までを事前固定し、
対象同一性が確定した次の別GOで日程/本文を扱う。今回は全て公式通信0。
当該都市の利用条件・料金・取得可能性が未確認ならNO-GO。
Ready・merge・Cloudflare・本番タスク・公開JSON更新は今回禁止のまま。

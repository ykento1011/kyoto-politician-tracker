# 議会のミカタ 京都 (Kyoto Politician Tracker)

> **AIは入口。判断するのは市民です。**

京都市会における議員の政策質疑ログ、本会議での採決・賛否データ、および選挙公報原本を構造化・整理し、市民が一次情報に基づいて市政と議会活動を確認・判断できるシビックテック・オープンデータプラットフォームです。

発言回数や文字数による「格付け」や、AIによる「議員評価（通信簿）」を目的とするものではありません。公開された議会記録を4つの観点から整理し、公約と議決・質疑の照合データを客観的に提示することで、市民と地方自治の対話を支援します。

---

## 🌟 主な機能

1. **質疑データ分析：政策分野と特徴**
   * 京都市会で交わされた全政策質疑スレッド（5,000件超）を統一8大政策分野へ分類し、質疑の多い政策分野TOP3を提示。
2. **4軸による質疑分析（レーダーチャート）**
   * 個々の質疑データを「根拠・データ」「対案・是正策」「地域解像度」「質疑の展開」の4つの分析軸（各0〜5点）から整理した客観的な分析値を表示。
   * ※議員の優劣や公式評価を示すものではありません。
3. **質疑スレッド構造化ビュー＆分析メモ**
   * 単なる発言の切り抜きではなく、「議員の質問 ➔ 行政側の答弁 ➔ 再質問」の一連の流れをタイムラインとして統合。
   * 「何を参照し、何を質問・提案し、行政がどう答えたか」の事実関係のみを記録した「分析メモ」を併記。
4. **議決・賛否の記録（賛否が分かれた議案フォーカス）**
   * 全会一致の案件を除外した「賛否が分かれた議案」を中心に、各会派および無所属議員の投票態度を記録。
   * 対立の論点、賛成側・反対側双方の主な論理を客観的に併記。
5. **看板公約と議会活動の照合（ファクト対比）**
   * 京都市選挙管理委員会の公式選挙公報原本（PDF）から候補者本人の看板公約を原文引用し、任期中の実際の議決態度（賛成/反対）および関連質疑ログを並列提示。
6. **松井市長 政策進捗トラッカー**
   * 市長マニフェスト、京都市基本計画、および予算配分データを結合し、市政公約のライフサイクルと予算規模を可視化。
7. **議員ポリシー比較モード**
   * 最大3名の議員を選択し、4軸分析チャートの重ね合わせ、質疑分野のポートフォリオ、および議決の一致状況を多角的に比較。

## 📐 分析方法（Methodology）

本プラットフォームでは、客観性と中立性を担保するために以下の仕様および分析基準を採用しています。

### 1. 4つの分析軸（質疑整理の物差し）

各質疑スレッドは、党派性や政策の賛否から独立した以下の4指標（各0〜5点）で整理されます。

| 分析軸 | 0〜2点 | 3点 | 4〜5点 |
| :--- | :--- | :--- | :--- |
| **根拠・データ**<br>*(Evidence)* | 一般的な状況確認、意見表明中心。 | 過去の実績、予算額、他都市事例等のファクトに言及。 | 条例条文、公的統計、公文書、具体的数値データの明示。 |
| **対案・是正策**<br>*(Solution)* | 現状確認、一般的な要望。 | 実務的な改善策や運用の選択肢の提示。 | 制度設計・財源を含む対案、または具体的な改善・見直しについて質問・提案した内容。 |
| **地域解像度**<br>*(Local Focus)* | 国政論や一般的な総論。 | 特定の行政区、担当部局、個別事業・制度への言及。 | 町名、学区、商店街、公共施設、交差点、路線名など生活現場の具体名に言及。 |
| **質疑の展開**<br>*(Constructive)* | 冒頭質問のみ、または単発の確認。 | 答弁内容を踏まえた論点の絞り込み・再確認。 | 答弁内容を踏まえ、制度の運用実態や今後の方向性について掘り下げて確認・質問した展開。 |

### 2. 分析メモ・要旨の生成原則

* **評価・講評表現の禁止:** 「最高水準」「前向き」「建設的」「鋭い」「手柄を引き出した」「迫った」などの成果強調や、「至らなかった」「乏しい」「終始した」などの減点理由・合否判定の記述を厳格に禁止しています。
* **事実記述の徹底:** 「[参照資料] を参照した質疑。[質問・提案項目] について質問し、行政側から [説明・答弁の要点] について説明があった質疑として整理されています。」という観察事実のフォーマットに統一しています。
* **決定論的出力の担保:** モデルの生成パラメータ `temperature` を **`0.0`** に固定し、同一データに対して常に同一の分析結果が出力される再現性を確保しています。
* **属性情報の遮断:** 議員の所属会派、当選回数、年齢、性別などの属性情報は分析プロンプトから排除しています。

## 🏛️ データソースとクレジット

本プロジェクトは、以下の一次情報源および公的オープンデータを利用しています。

1. **一次資料・公的情報源:**
   * [京都市会 公式会議録検索システム](https://www2.city.kyoto.lg.jp/shikai/)（本会議・常任委員会・特別委員会の会議録原本）
   * [京都市会 本会議 審議結果](https://www2.city.kyoto.lg.jp/shikai/honkaigi/)（議案採決結果・賛否データ）
   * [京都市選挙管理委員会 選挙公報原本（PDF）](https://www.city.kyoto.lg.jp/senkyo/)（2023年京都市議会議員選挙）
2. **政治議論データ基盤:**
   * [Sagebase (セージベース)](https://sage-base.com/)
   * 会議録の発言構造化、人物同定データを利用しています。
   * ライセンス: [Creative Commons Attribution 4.0 International (CC BY 4.0)](https://creativecommons.org/licenses/by/4.0/deed.ja)

## ⚠️ 免責事項・運営ポリシー

* **非党派性・中立性:** 本プラットフォームは特定の政党、政治団体、候補者を支持または批判するものではありません。
* **測定範囲の限界:** 本ツールの分析対象は「京都市会の議場および委員会室内で記録された公式会議録」および「公式議決記録」に限定されています。市民相談・陳情対応、地域活動、政策勉強会など、**議場外における重要な議員活動は本ツールの測定範囲外**です。

## 🛠️ 技術スタック

* **Frontend:**
  * React 19
  * Vite
  * Tailwind CSS
  * Recharts (データビジュアライゼーション)
  * Lucide React (アイコン)
* **Data Pipeline:**
  * Python 3.10+
  * BeautifulSoup4 / lxml (Webスクレイピング)
  * Google Gemini API (スレッド構造化・4軸データ整理)
  * Playwright (高精細OGPカード画像生成)
